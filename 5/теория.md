# Разложение числа на множители на эллиптической кривой

## Изоморфизм групп по КТО

Предположим, что число n раскладывается: `n=pq`, где `p != q` –
простые числа. Тогда по КТО имеет место изоморфизм групп:

```
ℤ/𝑛ℤ ≅ ℤ/𝑝ℤ ⊕ ℤ/𝑞ℤ
```

это означает что

```
x mod pq ↦ (x mod p, x mod q)
```

т.е. кажому `x mod pq` соответствует пара `(x mod p, x mod q)` и
наоборот

а в случае ЭК записывается так

```
𝐸(ℤ/𝑛ℤ) ≅ 𝐸(ℤ/𝑝ℤ) ⊕ 𝐸(ℤ/𝑞ℤ)
```

где `E(ℤ/𝑛ℤ)` - группа точек ЭК

Умножение любого элемента группы `𝐸(ℤ/𝑛ℤ)` на `𝑚 ∈ ℤ` сохраняет данный
изоморфизм:

```
m𝐸(ℤ/𝑛ℤ) ≅ m𝐸(ℤ/𝑝ℤ) ⊕ m𝐸(ℤ/𝑞ℤ)
```

## Аномалия в арифметике точек

В формуле сложения двух точек `𝑃1 = (𝑥1, 𝑦1)` и `𝑃2 = (𝑥2, 𝑦2)`
выражение для углового коэффициента имеет вид:

- Если `P1 = P2`: `(3 * x1^2 + A) / (2 * y1)`
- Если `P1 != P2`: `(y2 - y1) / (x2 - x1)`

В некоторых случаях может получиться так, что по модулю `p` точки
различны, а по модулю `q` одинаковы. Тогда формулы сложения точек
дадут неправильный результат, и сумма точек может не лежать на
исходной кривой.

> Точка P задаётся парой координат (x, y), где x, y — числа mod n.

> Например: n = 35, точка P = (10, 20).

> "Точка по модулю p = 5" — это пара: (x mod 5, y mod 5) = (10 mod 5,
> 20 mod 5) = (0, 0)

> "Точка по модулю q = 7" — это: (x mod 7, y mod 7) = (10 mod 7, 20
> mod 7) = (3, 6)

```
Дано:

p = 5
q = 7
n = p · q = 35
P₁ = (1, 2)
P₂ = (8, 2)

Точки разные по модулю p:

P₁ mod 5 = (1 mod 5, 2 mod 5) = (1, 2)
P₂ mod 5 = (8 mod 5, 2 mod 5) = (3, 2)

Точки одинаковые по модулю q:

P₁ mod 7 = (1 mod 7, 2 mod 7) = (1, 2)
P₂ mod 7 = (8 mod 7, 2 mod 7) = (1, 2)

Формула для P₁ ≠ P₂:

λ = (y₂ − y₁) / (x₂ − x₁) mod n
λ = (2 − 2) / (8 − 1) = 0 / 7 mod 35
λ = 0 / 7 mod 35

можно записать как

λ = 0 * 7^{-1} mod 35

где 7^{-1} mod 35 - обратный элемент к 7 по модулю 35

gcd(7, 35) = 7 != 1, значит обратного нет

т.е. нельзя посчитать λ и т.е. формула не работает

При одинаковых точках — другая формула вычисления λ, но проблема та же
```

т.е. надо проверить

```
d = НОД(n, λ₁), где λ₁ = знаменатель λ
```

если d не 1 и не n, то d — нетривиальный делитель n

Если при вычислении обратного элемента в формуле сложения точек
получилось `1 < gcd(λ₁, n) < n`, то gcd — нетривиальный делитель
n. **Задача факторизации n решена**.

## Алгоритм Ленстры - факторизации n через эллиптические кривые

Атака:

1. Выбрать точку `Q = (x0,y0)`, получить уравнение кривой (сгенерить
   A, вычислить `B = y0^2 - x0^3 - Ax0`)
2. Если на каком-то шаге (умножение - последовательные сложения,
   т.е. шаг=какое то из сложений в процессе умножения) `1 < gcd(λ₁, n)
   < n` то gcd — нетривиальный делитель n. Задача факторизации n
   решена.

Ключевой вопрос: как выбрать k?

Логика такая:

```
Хотим: получить 1 < gcd(λ₁, n) < n
    ↓
Нужно: λ₁ ≡ 0 (mod p), но λ₁ ≢ 0 (mod q)
    ↓
Это происходит при умножении на шаге, кратном r_p (порядку Q mod p), т.е. когда r_p · Q ≡ O (mod p)
    ↓
r_p является m-гладким: все его простые делители меньше некоторого m.
    ↓
r_p можно разложить как r_p = p₁^β₁ · p₂^β₂ · ... · p_s^β_s, где все pᵢ < m
    ↓
Значит, достаточно взять k = ∏ pᵢ^αᵢ по всем pᵢ < m
    ↓
Такое k делится на r_p (то есть k = r_p · t)
```

выбор `αᵢ`:

```
αᵢ нужно выбрать так, чтобы оно было ≥ βᵢ для любого возможного r_p.
    ↓
выбирается максимальное αᵢ такое что: pᵢ^αᵢ ≤ √n
```

k выбирается не случайно — а как произведение степеней маленьких
простых:

```
k = ∏ pᵢ^αᵢ по всем pᵢ ∈ D
```

- `D` - база разложения (мн-во простых чисел меньше какой то выбранной
  границы m)
- `αᵢ = ⌊0.5 · log n / log pᵢ⌋`

> αᵢ — это максимальная степень числа pᵢ, при которой: pᵢ^αᵢ ≤ √n

```
pᵢ^αᵢ ≤ √n  =>  pᵢ^αᵢ ≤ n^(0.5)

есть такое свойство: ln(a^b) = b · ln a

значит

αᵢ · ln pᵢ ≤ 0.5 · ln n

Делим обе части на ln pᵢ:

αᵢ ≤ 0.5 · ln n / ln pᵢ

Так как αᵢ — целое (степень), берём целую часть:

αᵢ = ⌊0.5 · ln n / ln pᵢ⌋
```

как выбрать m?

есть такая теореме: вероятность, что случайное число около n является
m-гладким:

```
P ≈ u^(-u), где u = ln n / ln m
```

Чем больше m, тем выше вероятность — но тем дороже вычисления.

```
P(r_p гладкое) ≈ u^(−u), где u = ln r_p / ln m ≈ ln p / ln m
```

Мы не знаем p, но знаем, что он ≤ √n, можно взять √n но это худший
случай

Практически ECM использует итеративное увеличение m, пока не найдёт
делитель.
